# Handoff：DSH crew 插件（三档委派 + 默认工具屏蔽）部署收尾

## Goal

控制 DSH（DeepSeek Harness）的委派成本：把"子代理继承父模型"的默认行为替换为
**固定路由的三档委派工具面** —— `subagent_quick`（便宜快，默认档）/
`subagent`（主力）/ `subagent_smart`（最强最贵，保留档）+ `create_agent`
（常驻角色代理）—— 模型只能"选档位"，永远不能选路由；并屏蔽所有 stock 委派
旁路（`subagent_fork` 继承父模型、`workflow` 脚本自由选 provider/model）。

背景动因：实测 2026-10-03/04 全部 workspace 的 `tool/call` 分布为
主力档 14 次 / 最贵 smart 4 次 / 便宜 quick 仅 2 次（系统性
over-escalation），且 stock 工具描述一字不差、无任何成本信号。

## Key decisions

1. **一个档位一个工具，语义写进各自 description**：工具定义是选型时最强的
   信号（stock 描述一字不差是 over-escalation 主因）；升级规则**失败驱动**
   （"quick 的结果不够用才升档"），不做难度预判。
2. **路由钉在插件 Config**（默认 quick=deepseek-official/deepseek-flash@max、
   workhorse=zai-coding-cn/glm-5.3@max、smart=openai-codex/gpt-6.1-sol@xhigh），
   工具不暴露 provider/model 参数；可在 patch 层或 Web 设置页改。
3. `create_agent` = 常驻角色代理：bootstrap 提示词让子代理确认角色后待命
   （API 无空 prompt 创建，这是最贴近等价物），恒后台，后续
   `send_message` 投任务。
4. `subagent_fork` 关闭（继承父模型=旁路；钉别的模型丢 KV 前缀复用，不划算）；
   `workflow`+`workflow-ptc` 关闭（最后一条自由选路旁路）—— 均为用户拍板。
5. **preset-standard 声明覆盖**替代顶层 disable：loader 按 id 的 patch 打不进
   组内嵌套行（2026-10-06 实测）；代价 = 升级 dsh 后必须重新 diff 官方
   standard 预设同步重述。
6. 保留 `tool-subagent-control` / `tool-subagent-list-agents`（send_message /
   interrupt_agent / list_agents 是 crew 的控制面）。
7. 插件要求 provider（spawn）具备 `agentOptions` + `prepareContinuable` 能力，
   缺则挂载即报错（fail loud）。
