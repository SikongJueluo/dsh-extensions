## Key decisions

1. **双覆盖 standard+cordis**：Web UI 新开对话预设不可控（记住最近选择），
   只盖 standard 必然漏。ptc **不覆盖**（用户拍板：0/119 使用，少一份升级
   diff 负担；启用前需按同手法重述，patch 文件头已注释）。
2. **customSkillDirs 锚点改写**：cordis 预设 `skill-filesystem` 的
   `customSkillDirs` 官方用 `!!js createRequire(baseUrl)` 相对解析，而
   loader（@deepseek-ai/cordis-plugin-loader）的 `baseUrl` 绑定"贡献该行
   的 patch 文件"（EntryTree ctx 继承链 + `evaluate = with(ctx){eval}`），
   重述进用户层文件后解析链必 MODULE_NOT_FOUND。改为
   `createRequire(process.argv[1])`（dsh 的 bin.js，升级稳定），node 单测
   解析到同一 skills 目录。
3. **离线验证方法论**（沙箱限制下的可行通道）：会话沙箱内
   `dsh --dump-config` 会写 `profiles/<p>/cordis.yml` → EROFS；`/tmp` 在
   bash 沙箱内按调用隔离（写读需同一命令）。解法：工作区建临时目录放
   `DSH_HOME`（copy `~/.dsh/profiles/web` 含 node_modules，仅 12K），按
   ExecStart 顺序传同样的 `--patch` 链。
4. 排查工具链：会话预设/创建时间看
   `~/.dsh/sessions/<workspace>--/<id>/session.v4.jsonl.zstd` 头行
   （`zstd -dc` 后 `agentPreset`/`createdAt`）；部署真相同
   `~/.config/systemd/user/dsh-web.service`（HM-as-module 装在 home）的
   ExecStart store 路径 diff 源文件；服务重启史看 `journalctl
   _SYSTEMD_USER_UNIT=dsh-web.service _UID=1000`（用户总线在沙箱内连不上，
   systemctl --user 不可用）。
5. nixos 仓的 jj 描述留给用户（工作副本 @ polmuytw 可能属用户并行会话，
   不动）；dsh-extensions 的 @ 留有 plan doc 更新也未描述。
