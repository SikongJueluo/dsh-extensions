# 源码注释规则

本规则仅适用于本仓库，包括存量代码。注释是可选的接口说明，不是必须填写的模板。

## 允许的位置与额度

| 位置或内容 | 上限 |
| --- | --- |
| 文件顶部的文件说明 | 5 个内容行 |
| 类、函数、方法、`interface`、`type` 声明的总体说明 | 每个声明 3 个内容行 |
| 每个参数的 `@param` 说明 | 每个参数 1 行，不占总体 3 行 |
| `@returns` 说明 | 每个函数 1 行，不占总体 3 行 |
| 每种异常的 `@throws` 说明 | 每种异常 1 行，不占总体 3 行 |
| 每个物理内容行 | 最多 100 个按空白分隔的词 |

字段、普通变量、函数体内语句和行尾不放说明性注释。函数或类赋给变量时，说明归属于该函数或类，而非普通变量。
嵌套函数的声明说明仍按函数规则处理；它不使函数体内其他注释合法。

额度按物理内容行计算：去掉注释语法前缀后，空白行仍占额度；单独的起止定界符不计数。
同一文件或声明前的多个说明块合并计数，拆块不能增加额度。参数、返回值和异常不能换行续写，也不能重复标签以拆分说明。

## 格式与语言

- 所有说明性注释用英文；正文只允许可打印 ASCII 字符，另允许换行和必要的缩进制表符。
- JS/TS 使用 `/** ... */` 文档注释；文件说明放在顶部，用非空的 `@module` 标识模块，标记本身占文件的 5 行额度。
- Python 使用模块、类、函数的文档字符串；CSS、YAML、JSONC 使用本语言的注释格式，只允许顶部文件说明。
- 块级标签仅允许 `@module`、`@param`、`@returns`、`@throws`，且分别用于文件说明或函数契约。`@module` 必须有模块标识；参数和异常标签必须有对象标识及非空说明，返回值标签必须有非空说明。
- 正文允许内联 `{@link ...}`；它不增加额度。示例、弃用记录、扩展备注等不另设标签或额外额度。

参数和异常按实际对象区分，不给同一对象重复写标签。返回值只写一条。
只有名称和类型不足以表达的信息才需要说明，例如单位、范围、所有权、特殊返回值和异常触发条件。

```ts
/** @module time/normalize */

/**
 * Accepts UTC timestamps only.
 * @param value - Unix time in milliseconds.
 * @returns An ISO 8601 UTC timestamp.
 * @throws {RangeError} When the timestamp is outside the supported range.
 */
export function normalize(value: number): string {
  return new Date(value).toISOString()
}
```

## 内容风格

说明只保留职责、必要约束，以及从代码和类型中不明显的原因。优先让命名、类型和测试表达行为。
不复述实现步骤，不写教程、变更记录、装饰分隔线，不保留注释掉的代码。

有独立维护价值的设计理由和使用示例写进对应文档；清理注释不是把全部旧注释原样搬到 Markdown。
许可证和第三方归属信息集中保存在专用的 `LICENSE`、`NOTICE` 等文件中，迁移时保留必须的信息，不为源码版权头设置一概豁免。

## 工具指令例外

仅解析器识别、工具确实需要的指令注释可出现在普通说明禁止的位置；例如 lint 抑制、类型检查或构建指令。
指令例外不等于允许任意带工具名的说明，也不允许借指令附加无关长文。

现有 lint 抑制仍由 [质量门禁 §6](quality-gates.md#6-批准清单) 和 `check:suppressions` 登记校验；新增指令不能绕过原有审批。
解释性 TODO、许可证头和任意“特殊注释”不自动成为指令。

## 静态检查与审查

- `pnpm check:comments`：解析源文件，检查位置、格式、标签、额度和字符范围；违规返回非零退出码。
- `pnpm test:comments`：运行检查器的回归测试，包括合法边界、越界样例，以及字符串中的伪注释。
- `pnpm check:quality`：在前段运行注释门禁及其回归测试；CI 复用同一入口。

检查覆盖本仓库手写的 TS/JS（含 TSX/JSX 及模块扩展名）、Python、CSS、YAML、JSONC 源码、测试、脚本和配置。
Markdown 文档正文、字符串或模板中的文本不作为源码注释；Python 声明位置的文档字符串除外。
依赖、构建产物、缓存和工具运行时数据不属于手写源码，不纳入扫描；不为历史违规建立基线或文件豁免。

ASCII 校验不能证明自然语言一定是英文，静态分析也不能完整判断说明是否复述实现、是否有价值、指令是否必要。
这些属于审查要求，不以自动检查通过替代。修改检查范围或放宽规则遵守 [质量门禁](quality-gates.md) 的审批要求。
